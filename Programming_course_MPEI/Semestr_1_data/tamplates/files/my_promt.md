**ЖЁСТКИЕ ПРАВИЛА (НАРУШЕНИЕ = ОШИБКА)**  

1. **НИКАКИХ «НАНОВ» И БОЛТОВНИ**  
   - Запрещено писать приветствия, пояснения, рассуждения, комментарии внутри кода или вступления. Выдавай строго запрашиваемый результат (два файла кода).

2. **ЗАПРЕТ НА ОПТИМИЗАЦИЮ**  
   - Не объединять циклы, даже если они идут подряд.  
   - Не выносить повторяющийся код в отдельные негласные функции, если это не предусмотрено шаблоном.  
   - Не использовать `break`/`continue`, если их нет в эталоне.  
   - Сохранять «неэффективные» или прямые конструктивные решения (например, несколько проходов по массиву, если так заложено в архитектуре эталона).

3. **ОДИН RETURN В ФУНКЦИИ**  
   - Каждая функция (включая `main`) должна иметь ровно один `return` (или пустой `return` для `void`) в самом конце.  
   - Запрещены ранние выходы (`return` в середине функции, в ветвлениях `if-else`).  
   - Все проверки и ветвления оформляются через вложенные `if-else`, а не через досрочный выход из функции.

4. **ПОЭТАПНОСТЬ ЧЕРЕЗ ФЛАГИ И СЧЕТЧИКИ**  
   - Не смешивай проверку условий и саму обработку в одну кучу.  
   - Следуй логике эталона (как в примерах с проверкой наличия условий): сначала отдельная функция или этап проверяет условие (например, подсчет элементов или поиск признака), фиксирует результат во флаге/счетчике (`int flag = 0;` / `kA`, `kB`), и только на следующем шаге (если флаг соответствует условию) запускается выполнение целевой функции.  
   - Монотонно повторяй эту структуру для каждого массива или файла, без хитрых ухищрений.

5. **ФЛАГИ BOOL ИЗ STDBOOL.H**  
   - Используй `bool` из `<stdbool.h>` для функций проверки (`Exist...`), как в эталоне `functions.h`.  
   - Для счетчиков и индексов используй `int` (`kA`, `kB`, `i`).  
   - Проверка состояния — через `if (flag == true)` или `if (flag == false)`.

6. **ЗАПРЕТ НА NULL**  
   - **Не использовать** `NULL` вообще. Вместо этого:  
     - Объявление указателей: `float *A;` (без инициализации) или `float *A = 0;`  
     - Проверка указателей: `if (A == 0)` или `if (!A)`  
     - Присвоение после `free`: `*x = 0;`  
   - В эталоне `VvodVect` нет проверки `malloc` на `NULL` — копируй это поведение (не проверять).

**СТИЛЬ КОДИРОВАНИЯ (КОПИРОВАТЬ С ЭТАЛОНА)**  
- **Имена функций**: Транслит (`VvodVect`, `VivodVect`, `CountNegative`, `ExistGreater`, `ObrabotkaMatrix`, `FreeMemoryVector`).  
- **Имена переменных**: Короткие, с суффиксами A/B/C для разных массивов (`nA`, `nB`, `kA`, `kB`, `fp`, `out`, `mA` для матриц).  
- **Проверка ошибок**: Всегда проверять результат `fscanf`, `fopen` в `main` (но не в `VvodVect`).  
- **Освобождение памяти**: Строго через отдельные функции `Free...` с обнулением указателя (`*x = 0`).  
- **Формат вывода**: `fprintf(out, "%f\n", x);` с `\n` в конце.  
- **Чистый C**: Никаких C++ элементов (никаких `cin/cout`, `new/delete`, ссылок `&` в аргументах функций, кроме двойных указателей `**` для выделения памяти).
