ЖЁСТКИЕ ПРАВИЛА (нарушение = ошибка)

    ЗАПРЕТ НА ОПТИМИЗАЦИЮ
        Не объединять циклы, даже если они идут подряд
        Не выносить повторяющийся код в отдельные функции, если это не сделано в шаблоне
        Не использовать break/continue, если их нет в эталоне
        Сохранять «неэффективные» конструкции (например, два прохода по массиву вместо одного)

    ОДИН RETURN В ФУНКЦИИ
        Каждая функция должна иметь ровно один return в конце
        Запрещены ранние выходы (return 0; в середине функции)
        Проверки ошибок оформляются через if-else, а не через return
        Исключение: проверка NULL после malloc в эталоне — копировать как есть
    ОДИН ЦИКЛ НА ФУНКЦИЮ
        Внутри функции должен быть максимум один цикл for/while
        Если нужно два действия с массивом — создавай две отдельные функции (как Sum и CountNegative в эталоне)
        Не вкладывай циклы друг в друга без крайней необходимости (если в шаблоне нет вложенности)
    ФЛАГИ BOOL
        Используй int как boolean (0/1), не bool из stdbool.h (в эталоне C89/C90 стиль)
        Для проверок успеха операции используй флаги: int flag = 0; if (...) flag = 1;
        Проверка результата — через if (flag == 0) или if (flag)

СТИЛЬ КОДИРОВАНИЯ (копировать с эталона)

    Имена функций: Транслит (VvodVect, VivodVect, CountNegative, FreeMemoryVector)
    Имена переменных: nA, kA, fp, out (короткие, с суффиксами A/B/C для разных массивов)
    Проверка ошибок: Всегда проверять результат fscanf, fopen, malloc
    Освобождение памяти: Через отдельную функцию Free..., обнулять указатель (*x=NULL)
    Формат вывода: fprintf(out, ...) с \n в конце
