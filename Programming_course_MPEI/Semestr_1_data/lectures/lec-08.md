# Лекция 8. Структурное программирование и подпрограммы (часть 1)

**Источник:** Лекция 8-9.pptx
**Диалект:** C (C99/C11) — теоретическая база

## 1. Методология структурного программирования (слайд 2)

- задание хорошей топологии программ
- отказ от использования глобальных данных
- отказ от оператора безусловного перехода
- разработка модулей с максимальной скрытностью и независимостью от остального кода

## 2. Базовые принципы (слайд 3)

- Преимущественное использование базовых алгоритмических структур: следование, развитие, цикл
- Метод нисходящего проектирования алгоритмов
- Использование обозначений, соответствующих содержанию задачи и облегчающих понимание программы

## 3. Постулаты Эдсгера Дейкстры (слайд 4)

- Для любой неструктурной программы существует эквивалентная ей структурная программа
- Две программы эквивалентны, если для любых входных данных результаты их работы совпадают
- Структурная программа состоит только из конструкций следование, ветвление и повторение
- Для любой (не обязательно осмысленной!) программы с операторами Goto существует эквивалентная ей программа без операторов Goto

## 4. Не структурные операторы (слайд 5)

| Оператор | Смысл применения |
|----------|------------------|
| go to | Прямой безусловный переход к определенной точке программы, помеченный специальной меткой (label). |
| break | 1. Служит для прерывания циклов.<br/>2. В некоторых языках может быть частью синтаксической конструкции, но смысл его тот же – прерывание выполнения набора команд какого-то синтаксического блока. |
| continue | Служит для пропуска всех строк блока после continue до конца одной итерации цикла; при этом сам цикл не прерывается, а продолжает работу со следующей итерации. |
| exit | Принудительное завершение программного блока (зависит от точки вызова) |

## 5. Метод нисходящего проектирования алгоритмов (слайд 6)

- разделение задачи на связанные между собой подзадачи;
- алгоритм каждой подзадачи имеет один вход и один выход;
- разбиение на подзадачи отражает логику программы;
- алгоритм, устанавливающий связи между подзадачами, строится с использованием базовых алгоритмических структур;
- подзадачи автономны - кодируются как подпрограммы, преимущественно использующие локальные переменные

## 6. Что такое подпрограмма? (слайд 7)

> Подпрограмма - это отдельная часть программы, имеющая имя и решающая свою отдельную задачу. Располагается подпрограмма в начале основной программы (префиксное описание) или в конце основной программы (постиксное) и может быть запущена (вызвана) из основной программы по указанию имени.

## 11. Использование подпрограмм (слайд 12)

- сокращает исходный текст программного кода;
- сокращает объем исполняемого кода;
- повышает надёжность программы за счет:
  - уменьшения строк, в которых возможно допустить ошибку;
  - повышения читабельности кода, ясной логики программы;
  - сокрытия видимости переменных путем их локализации;
- увеличивает гибкость и функциональность кода, так как позволяет создавать и использовать так называемые **библиотеки** – сборник подпрограмм или объектов для решения близких по тематике задач;
- является необходимым условием многомодульной организации программных продуктов, без которых не возможна современная технология программирования.

```c
    <раздел описаний>

}
```
