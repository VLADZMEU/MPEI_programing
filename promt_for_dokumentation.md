# 2. ОБЩИЕ СТАНДАРТЫ ОФОРМЛЕНИЯ

## 2.1. Размеры массивов

Стандартное ограничение для размера массива:

**n ∈ [1;10]**

Размер массива не должен превышать 10 элементов.

Это стандартное ограничение для всех массивов программы, если в условии конкретной задачи явно не указано иное.

Для двумерных массивов каждая размерность по умолчанию также находится в диапазоне [1;10]:

- количество строк: n ∈ [1;10];
- количество столбцов: m ∈ [1;10].

Если в программе несколько массивов, для каждого укажи его размерность и ограничения.

Обязательно отражай эти ограничения в УПЗ, таблице данных, входной форме, блок-схеме и тестах.

### Обработка неправильного размера

Если пользователь вводит n<1 или n>10:

1. Программа должна обнаружить аномалию.
2. Вывести сообщение об ошибке или просьбу повторить ввод.
3. Повторно запросить размер массива.
4. Продолжить выполнение только после получения допустимого значения.

Если исходный код не реализует такое поведение, обязательно укажи это как ошибку программы. Не изображай повторный ввод на блок-схеме, если его фактически нет в коде.

Для двумерного массива отдельно покажи, что сначала вводится размерность, а затем элементы массива.

Для нескольких массивов разделяй ввод каждого массива.

Входная форма должна соответствовать реальной последовательности `scanf` и других функций ввода.

Не допускай, чтобы изменение счётчика оказалось вне тела или в неправильной части алгоритма.

Перед таблицей укажи полную сигнатуру функции в точности как в коде.

Например:

`int inputText(char *a, int n)`

Затем укажи:

**Назначение:** что делает функция.

**Входные параметры:** перечисли все параметры, которые принимает функция.

**Выходные параметры:** укажи возвращаемое значение и данные, которые функция изменяет через указатели или ссылки в доступном для C виде.

**Алгоритм работы:** кратко объясни внутреннюю последовательность действий.

Не придумывай параметры и результаты, которых нет в реальной сигнатуре и реализации.

Если функция возвращает `void`, обязательно это укажи.

Если функция изменяет переданный массив, отрази это как изменение выходных данных.

### 2. Отдельная таблица переменных подпрограммы

**Каждая функция обязательно имеет собственную таблицу.**

Используй структуру:

| Класс | Имя | Тип | Структура | Смысл | Формат | Диапазон |

Переменные группируй по классам:

**Вход:**
- параметры функции;
- исходные массивы;
- входные указатели;
- размеры и другие входные данные.

**Промежуточные:**
- локальные переменные;
- индексы;
- счётчики циклов;
- вспомогательные массивы;
- временные значения;
- флаги.

**Выход:**
- возвращаемое значение;
- изменённые массивы;
- выходные параметры;
- итоговые результаты.

Включай все переменные, объявленные и используемые внутри данной функции, а также все её параметры.

Не пропускай переменные циклов и временные переменные.

Для каждой переменной укажи:
- реальное имя;
- тип;
- структуру;
- назначение;
- формат;
- диапазон допустимых значений.

Используй стандартные форматы `%2d` для int и `%5.2f` для float.

Для каждого массива указывай размерность и ограничения.

Не копируй таблицу основной программы вместо таблицы функции.

Если функция использует параметры основной программы, всё равно отрази их в её собственной таблице, поскольку они являются параметрами данной подпрограммы.

### 3. Отдельная блок-схема подпрограммы

После таблицы переменных размести отдельную блок-схему именно этой функции.

Для каждой подпрограммы создавай собственную блок-схему в diagrams.net.

Блок-схема должна точно соответствовать внутреннему коду функции.

В начале используй специальное обозначение подпрограммы, ориентируясь на предоставленный образец:

- сверху указываются входные параметры;
- в центральной части — название функции;
- в правом нижнем углу — выходные переменные или возвращаемое значение.

Пример:

Сигнатура:

`int inputText(char *a, int n)`

Входные параметры:
- a;
- n.

Название в центре блока:
- inputText.

Выходные данные:
- фактически возвращаемое значение;
- изменённые выходные параметры, если они имеются.

**Не используй обычный овал «Начало» вместо специального обозначения входа в подпрограмму.**

После обозначения подпрограммы подробно изобрази её внутренний алгоритм.

Используй стандартные обозначения:
- овалы — начало и конец внутреннего алгоритма, если это предусмотрено структурой схемы;
- параллелограммы — ввод и вывод;
- прямоугольники — вычисления и присваивания;
- ромбы — условия;
- стрелки — направление выполнения.

Все циклы должны соответствовать исходному коду:

- `for` остаётся `for`;
- `while` остаётся `while`;
- вложенные циклы сохраняют свою структуру;
- счётчики изменяются в правильных местах;
- все условия и ветви отображаются.

Если внутри функции есть проверка аномалии, она должна присутствовать в её блок-схеме.

Если функция возвращает результат через `return`, покажи передачу результата на выходе.

Не выдумывай дополнительные ветви и действия.

### 4. Количество схем

Количество отдельных схем должно совпадать с количеством подпрограмм в программе.

Например, если в коде:

- main;
- inputArray;
- processArray;
- outputResult;

то требуется:

1. Одна основная блок-схема `main` в пункте 7.
2. Отдельная таблица и отдельная блок-схема `inputArray`.
3. Отдельная таблица и отдельная блок-схема `processArray`.
4. Отдельная таблица и отдельная блок-схема `outputResult`.

Итого: одна основная схема и три самостоятельные схемы подпрограмм.

Не считай `main` дополнительной подпрограммой.

### 5. Финальная проверка подпрограмм

Перед завершением проверь:

- каждая ли подпрограмма найдена;
- у каждой ли подпрограммы есть сигнатура;
- есть ли описание назначения;
- перечислены ли входные параметры;
- перечислены ли выходные параметры;
- есть ли индивидуальная таблица переменных;
- все ли локальные переменные внесены в таблицу;
- есть ли отдельная блок-схема;
- правильно ли обозначен вход и выход функции;
- соответствует ли блок-схема исходному коду;
- правильно ли оформлены циклы;
- нет ли пропущенных или лишних действий.

**Наличие общей таблицы переменных и общей блок-схемы вместо отдельных материалов для функций считается ошибкой оформления.**

## 4.9. Тесты

Тестирование должно быть максимально полным.

**Минимум 12 тестов.**

Если для полноценной проверки требуется больше, добавляй больше.

Запрещено составлять тесты, которые отличаются только несущественными числами и проверяют один и тот же сценарий.

Используй таблицу:

| № | Входные данные | Результат | Смысл теста |
|---|---|---|---|

Обязательно включай подходящие для задачи сценарии:

1. Контрольный пример с обычными данными.
2. Минимально допустимый размер n=1.
3. Максимально допустимый размер n=10.
4. Размер n=0.
5. Размер n=11.
6. Повторный ввод после неправильного размера.
7. Минимальные значения элементов.
8. Максимальные значения элементов, если ограничения существуют.
9. Отрицательные элементы.
10. Нулевые элементы.
11. Все одинаковые элементы.
12. Несколько элементов, удовлетворяющих условию.
13. Отсутствие элементов, удовлетворяющих условию.
14. Граничное значение условия.
15. Разные значения в соседних строках или столбцах, если применимо.
16. Все элементы массива удовлетворяют условию.
17. Ни одного подходящего элемента.
18. Другие специфические аномалии задачи.

Это перечень возможных сценариев, а не требование применять каждый из них к любой задаче.

Для двумерных массивов дополнительно проверяй:

- одинаковые элементы в разных строках;
- одинаковые элементы в разных столбцах;
- строки или столбцы с полностью подходящими элементами;
- различные комбинации элементов;
- случаи, когда подходящих элементов нет.

Для задач с поиском проверяй:

- элемент в начале массива;
- элемент в конце массива;
- элемент в середине массива;
- несколько подходящих элементов;
- отсутствие искомого элемента.

Для задач с вычислениями проверяй:

- обычные значения;
- нули;
- отрицательные значения;
- граничные случаи;
- отсутствие данных для вычисления.

### Требования к результатам тестов

Каждый результат должен быть рассчитан вручную или проверен пошаговым выполнением алгоритма.

Не придумывай ожидаемые результаты.

Для каждого теста укажи:

- конкретные входные данные;
- полный ожидаемый результат;
- сообщение программы, если оно появляется;
- смысл проверки.

Для массивов указывай все элементы, а не только их размер.

Если программа после неправильного размера запрашивает повторный ввод, покажи всю последовательность:

1. Ввод неправильного значения.
2. Сообщение программы.
3. Повторный ввод.
4. Продолжение программы.
5. Итоговый результат.

После составления таблицы проверь, что:

- все условия программы протестированы;
- все ветви if/else пройдены хотя бы один раз;
- все циклы проверены;
- проверены граничные значения;
- все предусмотренные аномалии присутствуют;
- тесты не дублируют друг друга.

Нельзя считать тест полноценным, если в нём отсутствует конкретный ожидаемый результат.
